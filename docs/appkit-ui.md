# AppKit UI

The macOS application UI uses AppKit and Swift. `BrowserRootView` owns the normal and incognito window hierarchy; `BrowserWebAppRootView` owns installed web-app windows. Neither root uses SwiftUI or `NSHostingView`.

## State and layout

- `BrowserChromeModel` and its existing services remain the source of browser state and actions. Views observe model changes on the main run loop and retain native controls across updates.
- `BrowserWindowChromeLayout` calculates window geometry. A pinned sidebar reserves viewport width; a hover sidebar overlays the page. Toolbars reserve height, while extension side panels reserve only page width.
- `BrowserSidebarChromeView` owns the sidebar header, list, footer, and resize handle. `BrowserNativeSidebarState` owns selection, rename, paging, and the two-step Clear interaction. Tab drag/drop has one gesture owner and uses the same semantic tree for rendering, proposals and commits; see [sidebar-drag-and-drop.md](sidebar-drag-and-drop.md).
- The sidebar edge snaps to the default width within 14 pt, a double click restores the default, dragging below 82 pt hides the sidebar, and the width tops out at 500 pt. The minimum stays at the 224 pt default because the header has no compact layout.
- The sidebar sits on the window edge chosen in Settings (General → Sidebar position) or with View → Move Sidebar to the Right/Left. `BrowserWindowChromeLayout.sidebarPosition` mirrors the sidebar, content insets, extension panel, hover overlay and reveal edge; the resize handle moves to the edge facing the content, and the window controls stay in the sidebar header, as in Zen.
- Keyboard navigation lives in `BrowserChromeModel+SidebarItems`. `⌘1…⌘8` go to sidebar items 1–8 and `⌘9` to the last one, `⇧⌘]` / `⇧⌘[`, and the alternates `⌥⌘↓` / `⌥⌘↑`, select the next or previous item and wrap; `⌥⌘→` / `⌥⌘←` switch to the next or previous Space. Items follow the sidebar: app tiles first, then the visible pinned rows and the temporary tabs; a Split View counts once and returns to its focused pane. `⌘=`/`⌘-`/`⌘0` zoom the page (CEF keeps zoom per site; `zoomPercent` is read back from the selected page on selection and navigation), `⌘.` stops loading, leaving a tab with a playing video sends it to Picture in Picture and returning brings it back (Settings → Picture in Picture when leaving a tab; a probe without a gesture checks for a playing video first, and only then `Runtime.evaluate` runs with a user gesture, so other pages gain no activation; top document only, not for split panes that stay on screen), `⌥⌘I` opens the page's Developer Tools docked at the right of its pane and closes them again (Alloy-style pages only). CEF shows them in a Chrome-style window of their own and refuses a native parent on macOS, so `BrowserTabController` takes the window that appears after the request, makes it a borderless child window over the right part of the pane, shrinks the page beside it, rounds the corners it shares with the viewport, hides it while its tab is off screen, and gives it a drag handle on its inner edge; the DevTools browser has no client of ours and closes before CEF shuts down or when its page moves to another window, `⇧⌘T` (Restore Last Closed Tab) runs Undo when the latest undoable action closed a tab, keeping Undo's fresh sync identity; `⌘L` (Open Location) opens the compact current-page command bar with the selected tab's URL, `⇧⌘D` shows or hides the URL toolbar, `⌘E` (Open Extensions) opens the site control center of the visible URL controls, or points it at the page's top corner while they are hidden, `⌥⇧⌘C` copies the page as a Markdown link (`BrowserMarkdownLink`), and `⇧⌘J` (View Downloads) opens the sidebar footer's downloads list, pointing at the page's bottom corner on the sidebar side while the sidebar is hidden. The Go to Sidebar Item entries and the Next/Previous Tab alternates are hidden View menu items that keep their key equivalents; shortcuts show arrow keys as arrows. A default added in a later version yields to a key the user already assigned to another command (`BrowserShortcutStore.shortcut(for:)`). `⌘←` / `⌘→` are not Back/Forward alternates, because they would take line start and end from page text fields. Reveal Current Tab has no default, because macOS uses `⌃␣` to switch input sources; the command is in the View menu and opens a collapsed pinned section, scrolls the row into view and shows a hidden sidebar over the page until the pointer moves. OpenArc has no Library: Downloads stay in the sidebar footer popover and Archive in its own window.
- The menu bar has the standard Mac items: Services and Hide/Hide Others/Show All in the app menu, Close Window (`⇧⌘W`, since `⌘W` archives the tab) in File, and a Window menu with Minimize (`⌘M`), Zoom and Bring All to Front that AppKit fills with the window list and tiling items. Web-app windows get the same app and Window menus. These keys are reserved in the shortcut editor and reach the menu from non-Latin layouts through the physical-key monitor. The browser menu bar has Spaces (Next/Previous Space, one item per Space with its `⌃1…⌃4` key, Reset All Tabs in This Space, New Space; the reset also sits in the Space row menu: the shown pinned tab reloads its pinned page and hidden ones unload so they open there) and Tabs (Pin/Unpin, Duplicate, Rename, Reset to Original URL, Next/Previous Tab, Reveal Current Tab, New Folder with the selected tab (folders hold at least one tab here), Collapse/Expand All Folders, Clear temporary tabs) and File gains Capture Full Page; the Space list is rebuilt when the menu opens. Pin/Unpin has no default because `⌘D` is Add Bookmark here.
- Peek: a Shift-clicked link (`CEF_WOD_NEW_WINDOW` with a user gesture) opens in `BrowserPeekPanel`, a borderless child card at 84 % of the window with the host, Open as Tab and Close; Escape, Command-W, Close or a click on the window behind closes it. The page is its own CEF browser (`BrowserPeekClient`, same request context as tabs, tracked by the client manager so quitting waits for it); links that open new windows from it become tabs, and each card is a session that owns its panel until its page has closed, so a card closed early drops its late callbacks. Downloads from a card go to the window's list; a crashed card closes; Command-W closes the key card and page commands are off while it is key. Settings → Links → Open Shift-clicked links in Peek turns it off. The same card, standalone, is the small window: with Settings → Links → Open links from other apps in a small window (off by default, so links from other apps keep opening as tabs), such a link opens in a resizable window of its own with the traffic lights, the host and Open as Tab; Escape stays with its page. Each link gets its own window. Closing a card or small window by the user registers Undo Close Peek, which `⇧⌘T` also performs. Its host is an address field: a click or `⌘L` shows the full address selected, Enter loads the typed address or search (`BrowserNavigationResolver`), Escape restores it. `⌘O` opens a card or small window as a tab; `⇧⌘O` or a right-click on Open as Tab shows Open In with the window's Spaces, and the page becomes a tab of the chosen one. File → New Small Window (`⌥⌘N`) opens an empty one with the field focused; with Settings → Links → Open a small window with ⌥⌘N in any app (off by default), `BrowserGlobalHotKey` registers the same keys system-wide through Carbon, which needs no Accessibility permission. The panel handles these keys before the app's shortcuts (`BrowserPeekPanel.handleShortcut`). With Settings → Links → Open ⌥⌘-clicked links in a small window (off by default), an Option-Command-clicked link opens there too; Chromium reports it as a Command-click, so `IsOptionCommandClick` reads the held keys.
- Peek for links to other sites (off by default): `BrowserTabClient::OnBeforeBrowse` asks the model through `shouldPeekNavigation` before a clicked link (`TT_LINK`, GET, no redirect or back/forward) leaves a pinned tab or Favorite; when `BrowserSite.isSameSite` says the target is another registrable domain, the navigation is cancelled and the link opens in Peek. Sign-in pages on another site open in Peek too, which is why it is opt-in.
- Capture Area (`⇧⌘2`): `BrowserAreaCaptureOverlay` dims the selected page or focused pane and reports the dragged outline as fractions of the page; the engine clips `Page.captureScreenshot` to that part of the visual viewport and copies the PNG.
- Change Color in a Space's menu tints the window background with a system color (`BrowserSpaceColor`, `BrowserChromeBackgroundNSView.tint`), cross-fading on Space switches; None, the default, keeps it neutral.
- Change Icon in a tab's menu shows a symbol from the Space and folder palette instead of the favicon (`BrowserChromeModel.setIcon(_:forTabID:)`, local only); Use Site Icon removes it.
- Folder preview (Settings → General → Preview folders on hover, on by default): resting the pointer on a collapsed folder row for 0.5 s opens `BrowserFolderPreviewPanel` beside it on the page side, listing the folder's tabs and subfolder tabs in sidebar order with a search field. The panel is a non-activating child window that becomes key only when its search field is clicked, so hovering never takes the keyboard from the page. A click or Return opens a tab; leaving it for 0.25 s, Escape, expanding the folder, a drag or switching Spaces closes it.
- Links from Other Apps: Settings → Links lists `BrowserLinkRoute` rules (Site is / Address contains, then a Space of this profile or the small window) stored in `BrowserUserPreferencesStore.linkRoutes`. `BrowserApplicationController.openAboutLink` applies the first matching rule to http(s) links from other apps; a Space rule selects the Space in its profile's open window and opens a tab there. A rule whose window is closed or whose Space was deleted lets the link open as usual. Each rule has one condition.
- Boosts: New Boost (View menu, command bar, the sidebar's + menu, the site control center's brush button and its … menu) opens `BrowserBoostEditorViewController` in a borderless `BrowserBoostPanel` centered on the window's trailing edge, halfway down, a child window that moves with it (`BrowserBoostEditorPanelController`). Top to bottom: close, the name menu (Rename this Boost…, Reset All Edits, Delete this Boost) and undo; a color wheel whose light puck picks the tint's hue and saturation and whose dark puck its hue offset; Invert lightness, Advanced color controls (Contrast, Brightness, Original Saturation sliders) and Reset to original colors; a 5 × 4 font grid; Size (90–150 %) and Case menus; Zap, with the zapped elements and Restore under it while there are any; Code, which opens `BrowserBoostCodeViewController` beside it with CSS (applies as typed) and JavaScript (saved when its field loses focus, the tab changes or the editor closes; saving reloads the site's open pages). Every change applies at once and turns the Boost on. Zap outlines the element under the pointer; a click hides it and records a CSS selector, Escape ends zapping (the model polls the page's script, `BrowserChromeModel+Boosts`). The editor closes when the page moves to another site. Boosts live in `BrowserUserPreferencesStore.boosts`, one per host, covering its subdomains; the closest one that is on applies (`BrowserBoost`). Font, case, CSS and zaps reach every frame of the site; size and colors only the top document (`activePageStylesheet`): a `filter` on `html` with an SVG gradient map of the page's lightness for the tint (`BrowserBoostTintFilter`), `invert(1) hue-rotate(180deg)` for inverted lightness with media turned back, then `contrast()` and `brightness()`. `BrowserBoostCatalog` feeds both engines: CEF runs `BrowserBoostScript.documentScripts` in every frame from `OnLoadStart`, and WebKit pages install `webKitUserScripts` at document start; open tabs restyle in place or reload (`BrowserBoostRefresh`). The Library's Boosts section lists them with a switch (Rename…, Turn Off, Delete… in the menu; a click opens the site with its editor); the site control center shows the site's Boost, which a click turns on or off. Settings → Advanced → "Enable Boosts on websites you visit" stops every Boost without deleting it. Incognito windows run, edit and list none.
- Easels: New Easel (`⌃⇧E`, File menu, command bar, the sidebar's + menu) saves a drawing (`BrowserEaselDocument`, `BrowserEaselStore`: `Session[-suffix]/Easels/<id>/easel.json` and `images/`) and pins a tab at `openarc://easel/<id>` at the end of the Space's pinned tabs; the row follows the Easel's title and a rename of the row renames it. The engine serves an empty page there and `BrowserContentNSView` covers the tab's page, or its pane in a split, with `BrowserEaselView`: a canvas 1000 points wide that scales with the view and scrolls down, a toolbar at the bottom leading corner (Select V, Image, Text T, Circle O, Rectangle R, Arrow A, Pen P, then Capture) and Share (Share via…, Save as Image…, Copy as Image) at the trailing one. Shapes take the dragged rectangle (Shift keeps a square) and return to Select; the pen stays on. A selected shape shows the palette's colors above it, selected text +, Aa and − (paragraph style ultra…body, font clean/hip/fancy/mono) beside it. Objects move with alignment guides to other objects' edges and centers and the page center (⌘ turns them off while dragging), resize by their corners (pictures keep their shape), and have Bring to Front, Send to Back, Delete, Cut, Copy, Paste and Duplicate; the canvas menu has Paste, Color Palette (Vibrant, Chill) and Use Alignment Guides. Every edit is one step of the Easel's own Undo (`BrowserEaselEditor`). Pictures paste, drop or come from the Image tool. Capture: the toolbar button outlines part of the page beside the Easel in a split, or opens a split with the command bar; Capture Area's note offers Send to New Easel. A capture opens its page from its hover bar and, with Update from the Page, re-captures the same region of its open page every 5 s while the Easel is on screen (`captureTabRegion`). The Library's Easels section lists them with a picture of their top; the row menu has Remove Easel from Sidebar and Delete Easel. Sync carries only the pinned tab: a Mac without the drawing says so. Incognito, blank and web-app windows have no Easels.
- Pinned tabs restore unloaded at launch, with their last title, and load at the page they showed last when selected; the shown tab, split panes and Favorites load at launch (`restoreSessionIfAvailable`).
- Tab row menus offer Copy Link, Share, Rename, pinned URL actions, split actions, Duplicate (a temporary copy below a temporary tab, else at the top of the temporary tabs), Move to another Space (top of the same section), then Archive, Archive Other Tabs and Archive Tabs Above on temporary rows (temporary tabs only, a split counts as one) and Archive Tabs Below. Mute Tab silences the engine (`CefBrowserHost::SetAudioMuted`, reapplied when a page attaches) for this run, and the row shows a crossed-out speaker that unmutes; an audible indicator would need CEF's audio handler, which captures the streams, so it is not shown. Change Icon is not implemented (`BrowserChromeModel+TabActions`).
- `BrowserContentNSView` and `BrowserViewportClipView` embed the existing CEF host. The engine, navigation, persistence, and content lifecycle remain outside the UI layer.
- The root preserves the hover sidebar during fullscreen transitions and resumes pointer dismissal after actual pointer movement. Geometry animations ignore unrelated model notifications.

## Shared appearance and controls

Use `BrowserChromeColors` for adaptive colors and `BrowserChromeLayout` for dimensions. Reuse the native controls in `Sources/Browser/NativeUI`:

- `BrowserNativeSurface`, `BrowserNativeMaterialPanel`, and `BrowserChromeBackgroundNSView` provide fills, borders, clipping, and blur.
- `BrowserNativeChromeButton` and `BrowserNativePressableView` provide press, hover, keyboard/accessibility, and tooltip behavior.
- `BrowserNativeTooltipPresenter` shares the delayed tooltip coordinator and placement policy across controls.
- `BrowserNativeResizeHandle` shares delayed hover, cursor cleanup, haptics, and default-width snapping.
- `BrowserFaviconNSView` uses the existing favicon cache. Raster resizing continues through `BrowserImageThumbnailer`.

Native settings remain separate from Chromium's `openarc://settings` page. General → Import also brings in Arc's Spaces, pinned tabs, folders and Favorites from its `StorableSidebar.json` as dormant tabs (`BrowserImportedSidebar`, `importSidebar`). The welcome's import reads the same model from Cra's `sidebar.json`, Crest's `session.sqlite`, and the JSON files of the WebKit browsers Yab, Vane and Search (`BrowserWebKitAppImport`); a Space bound to a Chromium profile follows the OpenArc profile made for it. Vane is sandboxed, so only its container folder is checked until an import starts. General → Downloads holds the download location: the engine saves into the chosen folder through `BrowserDownloadLocation` while it exists and falls back to the user's Downloads folder; OpenArc keeps one location for the app. The Settings package hosts AppKit pane controllers. About, downloads, extension popovers, find, command input, bookmarks, and the tab switcher are native views/controllers.

Animation timing and state triggers are documented in [appkit-animations.md](appkit-animations.md).

## Verification

The Codex **Build** and **Test** actions remain separate, console-only actions:

```sh
./build.sh build
./build.sh test
```

Both scripts select Xcode 27.2. Format changed Swift files with the repository `.swiftformat` before Build. Unit tests use Swift Testing and cover models, native text editing, IME protection, selection, drag proposals, menus, clipping, and window geometry.

Build, Test, and offscreen control-rendering tests do not move the system pointer, inject keyboard events, or activate browser windows. Prefer them while the user works on the same desktop.

Live checks are explicit, opt-in actions requiring Accessibility permission. They move the real pointer and type into the foreground app; run them only when the user has made the desktop available. Launch an isolated browsing runtime before running them:

```sh
./build.sh run --skip-build --runtime-suffix appkit-ui-verification
export DEVELOPER_DIR=/Applications/Xcode-27.2.0.app/Contents/Developer
xcrun swift -swift-version 6 script/verify_appkit_sidebar_ui.swift .build/xcode/Build/Products/Debug/OpenArc.app
xcrun swift -swift-version 6 script/verify_appkit_site_ui.swift .build/xcode/Build/Products/Debug/OpenArc.app
xcrun swift -swift-version 6 script/verify_appkit_bookmarks_ui.swift .build/xcode/Build/Products/Debug/OpenArc.app
xcrun swift -swift-version 6 script/verify_appkit_window_ui.swift .build/xcode/Build/Products/Debug/OpenArc.app
xcrun swift -swift-version 6 script/verify_appkit_ui.swift .build/xcode/Build/Products/Debug/OpenArc.app
xcrun swift -swift-version 6 script/verify_appkit_webapp_ui.swift .build/xcode/Build/Products/Debug/OpenArc.app
```

Start window checks with a visible pinned sidebar and a normal, non-fullscreen window. The scripts use local fixtures and generated test titles. The runtime suffix isolates browser data and turns account sync off unless `OPENARC_SYNC_BASE_URL` names a server; application preferences are shared, so the checks restore the preferences they toggle. The general UI script ends in Settings. The web-app check creates its own temporary bundle configuration, loopback HTTP server, and application instance and stops that instance afterward.

These checks exercise actual AX controls and mouse/keyboard events: command suggestions, find, settings, rename commit/cancel/blur, reorder/pin/folders, Clear, spaces, downloads, site controls, bookmarks, CEF input, resize, hover reveal, fullscreen, incognito, and web-app toolbar behavior. They do not claim coverage of every third-party extension, authentication provider, network failure, or OS configuration.
